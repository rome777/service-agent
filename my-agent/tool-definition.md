### 도구 정의서: 재고 확인

#### 1. 도구 정의서

| 항목 | 내용 |
|---|---|
| 이름 | `check_stock` |
| 하는 일 한 문장 | 창고와 상품을 받아서 재고가 몇 개인지 확인만 한다. |
| 언제 쓰고 안 쓰는지 | 쓴다: 어느 창고에 어떤 상품이 몇 개 있는지 물을 때. 여러 창고, 여러 상품을 한 번에 물어도 된다<br>안 쓴다: 재고 숫자를 바꿔 달라고 할 때<br>안 쓴다: 가격이나 원가처럼 개수가 아닌 걸 물을 때<br>상품 번호(SKU)나 창고를 짐작해서 넣지 않는다. 모르면 비워 둔다 |
| 인자 스키마 | `skus`: 상품 번호 목록. 선택. 한 번에 1~10개, 번호 하나는 3~32자. 비우면 모든 상품을 확인하되, 상품 번호 순으로 20줄까지만 돌려준다<br>`warehouse_ids`: 창고 목록. 선택. `SEOUL-01`, `BUSAN-02` 중에서만 고른다. 비우면 두 창고를 모두 확인한다 |
| 반환 형식 | 창고와 상품마다 한 줄씩 `sku`, `warehouse_id`, `available_quantity` (지금 내줄 수 있는 개수), `checked_at` (확인한 시각)<br>20줄을 넘어 잘렸으면 `has_more: true` 를 붙인다. 이때는 상품 번호를 정해서 다시 물어 달라고 한다<br>그 밖의 정보는 돌려주지 않는다 |
| 실패 정의와 뒤 행동 | `WAREHOUSE_NOT_ALLOWED`: 없는 창고를 넣었다. 쓸 수 있는 창고 두 곳을 알려 주고 물어본다<br>`INVALID_SKU`: 없는 상품 번호다. 그 상품만 번호를 다시 물어보고, 나머지는 그대로 답한다<br>`TOO_MANY_ITEMS`: 상품이 10개를 넘었다. 나눠서 물어 달라고 한다<br>`INVENTORY_UNAVAILABLE`: 재고 시스템이 응답하지 않는다. 한 번 더 해 보고, 또 안 되면 지금은 확인할 수 없다고 말하고 멈춘다 |

#### 2. 실패 사례 리디자인

| 실패 사례 | 비어 있던 칸 | 보완 문장 |
|---|---|---|
| 없는 창고 코드를 지어 넣고 같은 오류를 계속 냈다 | 인자 스키마, 실패 뒤 행동 | 창고는 두 곳 중에서만 넣는다. 오류가 나면 다시 부르지 말고 어느 창고인지 물어본다. |
| 상품 번호를 모르는데 비슷한 상품을 골라 확인했다 | 인자 스키마, 실패 뒤 행동 | 상품 번호를 모르면 비슷한 걸 짐작해서 넣지 않는다. 비워 두고 불러서 실제 목록에서 찾는다. |
| 돌려받은 내부 원가를 답에 그대로 말했다 | 반환 형식 | 개수와 확인 시각만 돌려주고, 답할 때도 그것만 쓴다. |

#### 3. 실행 전 채점 기준

| 채점 기준 | 통과 조건 | 어디서 확인하나 |
|---|---|---|
| 스키마 준수 | 상품 번호는 1~10개, 창고는 `SEOUL-01`, `BUSAN-02` 중에서만 넣었고, 사용자가 말하지 않은 값은 넣지 않았다 | 도구를 부를 때 넣은 인자 |
| 호출 성공 | 결과 줄이 나왔거나, 정해 둔 오류 코드 중 하나가 나왔다 | 도구가 돌려준 결과 |
| 결과 사용 가능성 | 답에 개수와 확인 시각만 썼고, `has_more` 가 있으면 잘렸다고 말했다 | 최종 답 |
| 실패 처리 | 오류가 난 뒤 개수를 짐작해 말하지 않고, 다시 묻기·한 번 더 해 보기·멈추기 중 정해 둔 것을 했다 | 도구 호출과 최종 답 |
